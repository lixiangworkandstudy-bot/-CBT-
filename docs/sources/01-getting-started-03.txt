一、控制接口剖析与避坑
让机器狗走路，第一件事不是写代码，而是选对接口。V1.6.0 固件只保留一个实时底盘速度入口；而网络上大量旧教程，仍然指向一个已经被删除的话题。
🚨 历史陷阱：/vbot/sportmode_cmd 已彻底废弃在 V1.6.0 固件中，/vbot/sportmode_cmd 没有任何系统节点订阅。你向它发布多少条消息都会被静默丢弃：不报错、不提示、机器狗纹丝不动。看到旧博客或旧视频里出现这个话题，请立刻关掉——它不是“另一种写法”，而是已废弃接口。
官方唯一现行接口
V1.6.0 的实时底盘速度控制只有一个入口，参数如下：
项目官方规范说明
话题名称/vel_cmd官方唯一现行实时底盘速度接口
消息类型geometry_msgs/msg/Twistlinear.x 控制前进/后退，angular.z 控制转向
所属中间件ROS 2 Humble / Aorta Bridge计算主板与主控网关板之间的通信桥
Domain ID178必须设置 export ROS_DOMAIN_ID=178，与机器狗保持一致
发布频率10Hz ~ 20Hz（推荐 20Hz）低于该频率会被 500ms 看门狗判定为上层失联
Twist 消息有六个自由度字段，但底盘速度控制实际只消费其中两个：linear.x（线速度，单位 m/s）与 angular.z（角速度，单位 rad/s）。其余字段保持 0 即可，本课脚本也会在急停时把它们全部归零。
二、为什么必须维持 20Hz 连续发包
机器狗底层运控节点内置了通信看门狗（Hardware Watchdog）。它不信任“一条指令管一辈子”的控制方式——一旦上层控制节点崩溃或网络断开，机器狗必须自己停下来。
若在 0.5 秒（500ms）内没有收到任何新的速度指令，底层立即判定上层失联，自动进入安全悬停模式并归零速度
因此，单次发布一条消息，机器狗只会“抽搐一下”；必须以 10Hz ~ 20Hz 的周期持续投递速度向量
20Hz 意味着每 50ms 一帧：一个 500ms 窗口内有约 10 次投喂机会，网络抖动丢掉几帧也不至于触发悬停
看门狗时序：连续投喂 vs 断流超时（时间轴 0–1000ms）
0 ms250 ms500 ms750 ms1000 ms
20Hz 连续投喂每 50ms 一帧
中途断流（超时）最后一帧后不再投喂
500ms 无新指令 → 看门狗触发 / 自动悬停归零
正常投喂的 Twist 帧
断流超时区：速度归零并悬停
判定阈值：500ms
500ms 是安全底线，不是目标频率
看门狗只在“超过 500ms 没有新指令”时触发，但这并不意味着你可以每 499ms 发一帧。真实链路里还有网络抖动、调度延迟与消息排队；一旦某一帧迟到，机器狗就会突然悬停。稳定做法是把周期压到 50ms（20Hz），留出约 10 倍的容错余量。
⚠️ 不要用“手动发一条”做测试在终端里手动 ros2 topic pub 一条 Twist，间隔通常远超 500ms。机器狗只会抖一下，然后立刻悬停——这并不代表接口不通，而是你看门狗正常工作了。下一步，我们把连续投喂写进脚本。
三、编写生产级脚本 hello_motion.py
通过 lesson_02 的 ssh vbot 登录计算主板，在任意工作目录用 nano 或 vim 新建 hello_motion.py，把下面的源码原样贴入并保存。脚本只依赖 ROS 2 Humble 自带的 rclpy 与 geometry_msgs，不需要安装任何额外依赖。
动手前：先看懂四处关键设计
安全授权闸门：--confirm-motion 默认关闭；未授权时脚本在 rclpy.init() 之前就打印预览并 sys.exit(0)，不会创建发布者，更不会发出一条速度指令。
20Hz 心跳：create_timer(1.0 / 20.0) 每 50ms 回调一次，在设定时长内持续向 /vel_cmd 投喂 Twist。
零速急停：emergency_stop() 连续发布 5 次全零 Twist，每次间隔 20ms，避免单帧丢失导致机器狗仍收到旧速度。
异常兜底：KeyboardInterrupt 与 SystemExit 都会触发急停，finally 中销毁节点并关闭 rclpy，不给“卡在运动状态”留机会。
python复制
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
VBOT EDU 极速入门：/vel_cmd 20Hz 连续速度控制示例
版权所有 (C) 2026 VBOT 开发者社区
"""
import sys
import time
import argparse
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist
class VbotMotionController(Node):
def __init__(self, target_linear_x=0.2, target_angular_z=0.0, duration=3.0):
super().__init__('vbot_hello_motion_node')
# 创建发布者，连接到核心话题 /vel_cmd
self.publisher = self.create_publisher(Twist, '/vel_cmd', 10)
self.target_linear_x = target_linear_x
self.target_angular_z = target_angular_z
self.duration = duration
# 设定 20Hz 循环定时器 (0.05s)
self.frequency = 20.0
self.timer_period = 1.0 / self.frequency
self.timer = self.create_timer(self.timer_period, self.timer_callback)
self.start_time = time.time()
self.is_stopping = False
self.get_logger().info(f"🚀 控制节点已就绪：线速度={target_linear_x}m/s, 角速度={target_angular_z}rad/s, 持续={duration}s")
def timer_callback(self):
elapsed = time.time() - self.start_time
msg = Twist()
if elapsed < self.duration and not self.is_stopping:
# 正常前进阶段
msg.linear.x = float(self.target_linear_x)
msg.angular.z = float(self.target_angular_z)
self.publisher.publish(msg)
self.get_logger().info(f"[{elapsed:.2f}s] 发布速度: vx={msg.linear.x:.2f}, wz={msg.angular.z:.2f}", throttle_duration_sec=0.5)
else:
# 达到预定时间，发送零速度停车并安全退出
self.emergency_stop()
self.get_logger().info("🏁 动作执行完毕，已平稳停车！")
self.destroy_timer(self.timer)
raise SystemExit
def emergency_stop(self):
"""下发全零速度，确保硬件安全"""
self.is_stopping = True
stop_msg = Twist()
stop_msg.linear.x = 0.0
stop_msg.linear.y = 0.0
stop_msg.linear.z = 0.0
stop_msg.angular.x = 0.0
stop_msg.angular.y = 0.0
stop_msg.angular.z = 0.0
for _ in range(5):  # 连续投递 5 次确保送达
self.publisher.publish(stop_msg)
time.sleep(0.02)
def main():
parser = argparse.ArgumentParser(description="VBOT 基础运控 Hello World")
parser.add_argument("--speed", type=float, default=0.2, help="线速度 (m/s)，建议 0.1 ~ 0.5")
parser.add_argument("--turn", type=float, default=0.0, help="旋转角速度 (rad/s)")
parser.add_argument("--duration", type=float, default=3.0, help="运动持续时间 (秒)")
parser.add_argument("--confirm-motion", action="store_true", help="显式运动安全授权标志")
args = parser.parse_args()
if not args.confirm_motion:
print("⚠️ [安全保护拦截] 未指定 --confirm-motion 参数！")
print(f"👉 预览目标动作：以 {args.speed} m/s 前进，持续 {args.duration} 秒。")
print("若确认机器狗周围无人员与障碍物，请添加 --confirm-motion 重新执行。")
sys.exit(0)
rclpy.init()
controller = VbotMotionController(
target_linear_x=args.speed,
target_angular_z=args.turn,
duration=args.duration
)
try:
rclpy.spin(controller)
except (KeyboardInterrupt, SystemExit):
controller.get_logger().warn("⚠️ 接收到退出信号，紧急下发全零速度刹车！")
controller.emergency_stop()
finally:
controller.destroy_node()
rclpy.shutdown()
if __name__ == '__main__':
main()
读完之后：三重保护为什么缺一不可
授权闸门保证“没确认就不动”，避免复制粘贴后误触；20Hz timer保证“动起来不会因看门狗断流而突然悬停”；零速急停保证“结束或异常时一定停”。三者分别对应事前、事中、事后，任何一层都不能省。
🛑 脚本里的急停只是软件急停emergency_stop() 依赖 ROS 节点仍然存活、网络仍然通畅。如果进程被强杀、系统卡死或无线链路中断，它无法保证生效。物理急停开关永远优先，实跑时手不要离开它。

七、安全检查清单
按下回车之前，逐条核对下面四项。建议把这一节当作每次实跑的固定动作，而不是读一遍就忘的说明。
✅ 场地与监护至少 2m×2m 的平整、无障碍地面；首次实跑务必安排一人在旁监护，随时准备断电。
⚠️ 先跑离线预览先用不带 --confirm-motion 的命令确认速度与时长，再追加参数实跑；不要跳过预览直接实跑。
🛑 物理急停在手边手不要离开物理急停开关。软件急停 ≠ 物理急停：节点崩溃或网络断开时，只有物理急停可靠。
🔋 电池与关节温度上报数据前确认电池电量充足、关节温度正常，避免低电量保护或过热降频打断动作。
🚨 一条不满足，就不要加 --confirm-motion运动控制没有“先跑起来再说”。场地、监护、物理急停、离线预览四项中任何一项没准备好，都请停在这一步——机器狗不会因为你的代码写得漂亮就避开桌腿。
