# VBOT EDU 真机部署与现场验收

## 当前真实状态

Windows 本地产品、WSL Ubuntu 22.04 / ROS 2 Humble、真实 turtlesim 联动均已验证。电脑未连接机器狗；没有确认设备账号、授权、SDK 三件套或现场设备版本。`robot/bridge.py --mode vbot` 是基于文档编写的待验收适配器，不是已完成真机部署。

## 1. 核对文档和设备，选择板载路线

用户指定教程以应用 V1.6.0 为基准。手册同时推荐优先查阅 [VitaDynamics/vbot-lab](https://github.com/VitaDynamics/vbot-lab)。本次核对官方快照 `26bd51d9397a46ed3cc008abeb46c8b9f36f3279`。官方明确：Aorta 是原生总线，ROS 2 仅保留兼容子集；板载 DDS 桥接本机可用，不能只把 PC Domain 改成 178 就远程连接。

教程部分示例与官方话题映射存在差异，例如 IMU 在教程中出现带 `/lowlevel` 的写法，官方当前表格给出 `/imu_raw`。本项目不猜测传感器路由；实际使用前以现场发现的路由、类型、生产者与设备软件版本为准。`/vel_cmd` + `geometry_msgs/msg/Twist` 的兼容输入在官方表格中有对应关系；仍需现场核对。

首选部署：**网页服务与适配器都运行在机器狗计算主板，Windows 浏览器经 SSH 本地转发访问。** 这样不需要 WSL/Windows 跨网络 DDS 发现，不需要修改路由器、安全配置或板载服务。

```text
Windows 浏览器 localhost:8787
  → SSH local forwarding
  → 主板 127.0.0.1:8787 (Python app)
  → 本地短租约 → Python ROS adapter (20Hz)
  → /vel_cmd (Domain 178, rmw_fastrtps_cpp, localhost-only)
  → 系统已有 aorta_ros2_bridge → Aorta → 底盘
```

本版只实现短暂、低角速度、零线速度的提示映射。它不是点头、摇尾、趴下或呼吸动作；那些需要另外核对头部、灯光、音频或 RCP 接口。不要把二维 turtlesim 的结果描述成四足步态验证。

## 2. 先只读检查

由现场支持确认目标是 foot_quadruped EDU、权限可用、设备处于允许调试的状态。按官方连接指南配置有线链路和 SSH 账号，IP/密钥由现场提供，不在项目中硬编码。不要修改底层系统或开放公网端口。

设备 SSH 终端执行（Windows/WSL 的 `/opt/ros` 环境不能替代这些板载路径）：

```bash
whoami
test -x /opt/vita/aorta/bin/aorta
test -r /opt/vita/aorta/edu/edu_session.json5
test -r /opt/vita/ros/humble/setup.bash
test -r /opt/vita/aorta/ros/local_setup.bash
```

若任何必要文件缺失，停止并向支持确认版本；不要用 chmod、修改配置或启动自建桥接器来“修复”。

在本次终端加载官方环境，先不写 `.bashrc`：

```bash
export PATH="/opt/vita/aorta/bin:$PATH"
export ZENOH_SESSION_CONFIG_URI=/opt/vita/aorta/edu/edu_session.json5
source /opt/vita/ros/humble/setup.bash
source /opt/vita/aorta/ros/local_setup.bash
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export ROS_DOMAIN_ID=178
export ROS_LOCALHOST_ONLY=1
command -v aorta
command -v ros2
```

随后在支持指导下对设备进行有界只读发现：

```bash
timeout 5 aorta topic list
timeout 5 ros2 topic list -t
timeout 5 ros2 topic info /vel_cmd --verbose
```

核对消息类型、存在的桥接订阅端以及当前运行的运动/RCP 资源持有者。不要通过“先发一条速度看会不会动”检查环境。没有发布者并不证明设备无能力，没有订阅端也不能直接诊断为权限缺失；向技术支持确认。

## 3. 拷贝项目，只启动无动作的服务

只将应用文件复制到支持同意的用户目录，例如 `/userdata/vbot/manman-planet`，不覆盖设备的 Skills、AGENTS.md、服务或配置。原生 ROS 适配器使用板载 `rclpy` 和 `geometry_msgs`，核心网页不要求额外安装 Aorta Python SDK；若扩展为原生 SDK，则需下载匹配版本的 wheel、MANIFEST 和 SHA256SUMS 并单独验证，不能凭 ROS 安装推定 SDK 已配置。

板载项目目录：

```bash
python3 scripts/check_environment.py
python3 -m app.server
```

Windows 另开终端，将 `vbot@ROBOT_IP` 换成现场确认的地址：

```powershell
ssh -N -L 8787:127.0.0.1:8787 vbot@ROBOT_IP
```

若 Windows 已运行本地演示，可以改左侧端口：`-L 8790:127.0.0.1:8787`，浏览器打开 `http://localhost:8790`。主板适配器仍访问主板 `127.0.0.1:8787`。浏览器可以先完整完成四个活动，无需启动运动适配器。

## 4. dry-run 核对

从浏览器 URL 复制 `session`；在已加载官方环境的板载项目终端执行：

```bash
python3 -m robot.bridge --session SESSION_ID --mode vbot --duration 60
```

默认不会导入 ROS 或写设备。完成活动后查看 dry-run 输出是否只短暂出现 `angular_z=0.12`、`linear_x=0`，之后归零。休息、断开网页服务和过期会话应输出零。预览通过仍不构成真机控制已通过。

## 5. 成人隔离区域内的首次运动联调

需要现场人员同意，按设备要求准备平整开阔区域（教程至少 2m×2m）、监护人员与可及的物理急停。没有儿童在附近。支持确认机器人姿态、底盘状态与 RCP 控制资源没有冲突；此项目不擅自站起、趴下或解除安全锁。默认线速度为零、角速度不超过 0.12rad/s、单次服务提示最多 0.6秒，但这些软件参数不代表适用于所有姿态与场地。

```bash
python3 -m robot.bridge --session SESSION_ID --mode vbot --execute --confirm-motion --duration 60
```

上述执行另受板载路径、Domain、RMW 和 localhost-only 检查约束。检查通过不等于设备状态已安全，现场确认不能省略。若接口类型、板载库或设备行为不同，停下并记录问题；不要扩大速度/时长来试探。

## 6. 验收顺序与回退

| 验收 | 预期 | 失败处理 |
| --- | --- | --- |
| 服务启动 | 网页可访问；未授权无运动 | 保留网页离线演示 |
| dry-run 完成活动 | 一次短提示后归零 | 检查 session、状态、租约 |
| 真机首次提示 | 支持认可的微小提示且实际停止 | 立即停止，必要时物理急停 |
| 休息 | 不再签发提示，ROS 接收零速 | 不依赖网页，现场停止设备 |
| 服务退出 | 适配器租约失效、归零 | 检查实际停止，不继续演示 |
| 适配器超时/Ctrl+C | 尝试连续5条零速并退出 | 核对设备已停止，物理急停兜底 |

停止软件后观察设备状态；最终停止由设备安全机制和现场人员确认。每次记录设备版本、命令、时间、实际表现与现场支持意见，再更新“已完成真机部署”的提交状态。未通过前只能展示仿真，不把 dry-run、心跳或成功发布当作真机动作证据。

## 7. 提交给技术支持的具体问题

1. 本次分配的机器狗是否为 foot_quadruped EDU，应用版本及桥接配置是否匹配官方 V1.6.0 文档？
2. `aorta_ros2_bridge` 的 `/vel_cmd` 是否已开放，实际订阅端类型与底盘状态前提是什么？
3. 能否提供板载 SSH 访问、允许的应用目录和现场物理急停操作说明？
4. 更适合静态陪伴的头部/耳灯/音频接口具体有哪些？哪些默认会发声，是否支持低刺激配置？
5. 若后续加入 RCP，如何确认资源锁、取消与终态，不和底盘控制并发争抢？
6. 儿童相关展示是否有额外的拍摄/场地授权要求？本次先用成人模拟，不现场招募儿童测试。
